# Built-in plugins and their own redraws

A built-in moves to its own redraws (`redraw.rs`, `LIVE`) on a platform when the states it draws have been driven live on that platform, in a debug build, with `OPENCODE_PLUGIN_REDRAW=implicit` against its own redraws on the same events, and both drew the same frames and trees, changing on the same frame. A case counts only if each run shows more than one state, and at least one of a plugin's cases is a change that lands on a frame with no input behind it (a service event, a process or server answering, a timer): input asks for a frame whichever redraw rule is on, so a case driven only by input can't tell the two apart. A code check alone doesn't move it, and neither does a pass on another platform: the choice of redraw is shared code, but what delivers a plugin's events (a terminal's output, a process's exit, a timer, a socket's answer) is each platform's own. Keep this table and `LIVE` in step.

"live" in a platform's column means the built-in redraws only on its own signal there; "legacy" means it redraws after any script execution, as before.
